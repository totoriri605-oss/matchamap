# 말차요정지도 — User Flow

## 1. 문서 목적

이 문서는 사용자가 말차요정지도에 들어온 뒤
어떤 순서로 서비스를 사용하는지 정의한다.

페이지를 개별적으로 만드는 것보다
**사용자 행동이 자연스럽게 연결되는 것**을 우선한다.

---

현재 동작은 2026-09-20 코드 기준이다. 목표·권장 흐름은 별도로 표시한다.

## 2. 기본 탐색 흐름

가장 중요한 사용자 흐름:

```text
홈 접속
↓
카페 검색 또는 지역 선택
↓
취향 필터 선택
↓
지도와 카페 목록 확인
↓
카페 선택
↓
상세 페이지 확인
↓
즐겨찾기 저장
```

이 흐름이 끊기지 않아야 한다.

---

## 3. 지역 검색 흐름 — 현재

검색창에 성수를 입력하면 이름 또는 지역명에 성수가 포함된 카페가 나온다. 지역 버튼은 정확 일치 조건을 추가하며, 맛·옵션 필터와 함께 적용된다.

사용자:

```text
"성수"
```

입력

시스템:

```text
성수와 관련된 카페 조회
↓
지도 마커 갱신
↓
카페 카드 갱신
↓
검색 결과 개수 갱신
```

---

## 4. 카페 이름 검색

사용자:

```text
"오설록"
```

입력

시스템:

```text
카페 이름 부분 일치 검색
↓
관련 카페 표시
```

검색 결과가 없을 경우
빈 화면만 보여주지 말고 안내 문구를 표시한다.

예:

```text
조건에 맞는 카페를 찾지 못했어요.
검색어나 필터를 조금 바꿔보세요.
```

---

## 5. 취향 필터 흐름 — 표시 개선안

현재는 1~5점으로 입력하고 조건을 제출한다. 아래 3단계 표현은 목표 UI안이며 점수 대응은 미정이다. 실제 이상·이하 조건은 [FEATURES](FEATURES.md)를 따른다.

예:

```text
말차 진하기 = 진함
단맛 = 적음
우유맛 = 적음
```

선택

↓  

조건에 맞는 Cafe 조회

↓  

```text
지도 마커 변경
+
카페 카드 변경
+
결과 개수 변경
```

---

## 6. 필터 초기화 — 목표 정책

사용자가 `초기화` 버튼을 누르면:

```text
취향 조건 제거
↓
추가 옵션 제거
↓
기본 카페 목록 복원
↓
기본 지도 마커 복원
```

검색어와 지역을 유지할지, 모든 조건을 지울지는 UI 작업에서 명확히 결정한다. 현재 동작과 비교한 뒤 적용한다.

---

## 7. 지도 사용 흐름

```text
지도 마커 클릭
↓
간단한 카페 정보 팝업
↓
상세보기 클릭
↓
카페 상세 페이지
```

팝업에는 너무 많은 정보를 넣지 않는다.

현재 팝업은 아래 정보와 평균 평점·리뷰 수를 표시한다:

- 이미지
- 카페 이름
- 지역
- 대표 메뉴
- 가격
- 상세보기

---

## 8. 카페 카드 흐름

```text
카페 카드 확인
↓
카드 클릭
↓
상세 페이지
```

하트 버튼은 카드 이동과 별도로 작동해야 한다.

목표는 하트 조작과 카드 이동을 분리하는 것이다. 현재 서버는 안전한 `next` 반환 경로가 있으면 해당 경로로 이동하고, 없거나 유효하지 않으면 상세 페이지로 이동한다.

---

## 9. 즐겨찾기 흐름

로그인된 사용자 기준:

```text
하트 클릭
↓
즐겨찾기 저장
↓
아이콘 상태 변경
↓
즐겨찾기 페이지에서 확인
```

다시 클릭:

```text
즐겨찾기 제거
```

현재 즐겨찾기 변경과 목록은 로그인이 필요하며, 비로그인 요청은 로그인 페이지로 이동한다. 로그인 이전 POST 동작이 자동으로 재실행된다고 가정하지 않는다.

---

## 10. 카페 제보 흐름

```text
제보하기
↓
카페 정보 입력
↓
제출
↓
pending 상태 저장
↓
관리자 확인
↓
approved / rejected
```

현재 제보는 로그인 없이 가능하다. 관리자 작업은 다음으로 나뉜다.

- 승인으로 변경: 상태만 approved로 변경.
- 승인하고 Cafe로 등록: Cafe를 조회·생성하고 approved로 변경.
- 거절로 변경: 상태만 rejected로 변경.

따라서 승인 상태만 변경하면 Cafe가 자동 등록되지 않는다.

---

## 11. 모바일 사용자 흐름

모바일에서는 정보가 너무 한 화면에 몰리지 않도록 한다.

권장 순서:

```text
Hero
↓
검색
↓
지역 선택
↓
취향 필터
↓
지도
↓
카페 카드
```

취향 필터는 접었다 펼 수 있는 UI도 고려할 수 있다.

---

## 12. 향후 여행 사용자 흐름

해외 확장 후 예:

```text
일본 선택
↓
도쿄 선택
↓
시부야 선택
↓
"진한 말차 + 덜 단 맛"
↓
카페 검색
↓
즐겨찾기
```

현재 개발 단계에서는 이 흐름을 실제로 구현하지 않아도 되지만,
데이터 구조와 URL 구조가 향후 확장을 막지 않도록 한다.

---

## 13. 사용자 흐름 검증 질문

기능 구현 후 아래를 확인한다.

```text
처음 들어온 사람이 다음에 뭘 눌러야 할지 알 수 있는가?
검색 결과가 지도와 목록에 동시에 반영되는가?
카페 상세 페이지까지 자연스럽게 이동할 수 있는가?
즐겨찾기를 쉽게 저장하고 다시 찾을 수 있는가?
모바일에서도 같은 흐름이 가능한가?
```

## 14. 리뷰 흐름 — 현재

카페 상세 → 로그인 → 별점(1~5)과 한줄평(최대 200자) 제출 → 리뷰와 집계 확인.
사용자당 카페별 1개만 작성할 수 있다. 잘못된 입력은 오류를 표시하고, 본인 리뷰는 삭제할 수 있다. 리뷰 수정 화면은 없다.

## 15. 취향 추천 흐름 — 현재

`/recommendations/` → 다섯 맛 선호 점수 입력 → 필수 옵션 선택 → 제출 → 최대 3곳 확인 → 상세 페이지 탐색.
맛 점수가 모두 있는 카페 중 점수 차이가 작은 순서로 추천한다. 자연어 AI 추천은 향후 후보이며 현재는 숫자 기반 계산이다.

## 16. 공통 예외

좌표가 없는 카페는 카드와 결과 개수에는 포함하지만 지도에서는 제외한다. 검색 결과가 없거나 추천 대상이 없는 경우의 안내도 화면 확인 범위에 포함한다.
